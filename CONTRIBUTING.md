# Contributing to the CASE Method

We accept proposals that make CASE shorter, clearer, or more reproducible.

A method change must:

- state the problem with the current method;
- define the exact proposed behavior;
- update the README and worked example to match; and
- add the user-visible change under `Unreleased` in the changelog.

For an editorial correction, provide the corrected text and its reason. Keep every change focused on the published method and its reader-facing examples.
